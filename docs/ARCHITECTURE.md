# Prod.io — Technical Architecture

## Stack

| Layer | Choice | Why |
|---|---|---|
| Language | TypeScript (strict) | Type safety across a large simulation |
| Build | Vite | Fast dev server and builds |
| World rendering | Phaser 4 | Mature 2D engine: tilemaps, sprites, cameras, input |
| UI (menus, phone, DAW, dashboards) | Preact + CSS overlay above the Phaser canvas | Rich, crisp, accessible UI is far easier in the DOM than in canvas |
| Audio | Web Audio API (possibly Tone.js) | Step sequencer playback with real samples |
| Tests | Vitest | Fast unit tests for simulation logic |
| Saves | IndexedDB (localStorage fallback) | Large save files, versioned |
| Desktop (later) | Tauri or Electron | Steam/desktop builds |

## Core principle: the simulation is separate from the view

```
┌───────────────────────────────────────────────┐
│  View layer                                   │
│  Phaser scenes (city, interiors)  +  UI overlay│
│  reads state, sends Commands                  │
└───────────────▲───────────────────┬───────────┘
                │ events / snapshots│ commands
┌───────────────┴───────────────────▼───────────┐
│  Simulation core (pure TypeScript, no Phaser) │
│  Clock → Systems → World state                │
│  deterministic, seeded RNG, fully testable    │
└───────────────────────────────────────────────┘
```

- The **simulation core** has no rendering code. It can run headless in tests, which
  lets us simulate years of the economy in seconds to balance it.
- The **view** never changes state directly. It issues **commands**
  (`ProduceBeat`, `ListBeat`, `PostToInstaSnap`, `SignContract`...) which systems validate and apply.
- Systems announce changes on a typed **event bus** (`BeatSold`, `DayStarted`,
  `RelationshipChanged`...) which drives the UI, notifications and other systems.

## Simulation core

- **Clock**: in-game minutes. Real-time with pause, 1x / 2x / 4x. Systems subscribe to
  minute, hour, day, week and month ticks.
- **World state**: one serializable object made of plain data (no class instances),
  stored in normalized tables by ID (`artists`, `beats`, `songs`, `companies`, `contracts`, ...).
- **Systems**: each owns one domain and runs on ticks.
  - `NeedsSystem`, `SkillSystem`, `ProductionSystem`
  - `MarketSystem` (BeatHub), `LoopMarketSystem` (LoopVault)
  - `PlatformSystem` (streams, views, followers, payouts)
  - `SocialSystem` (posts, reach, DMs), `RelationshipSystem`
  - `TrendSystem`, `NpcCareerSystem`, `ReleaseSystem`, `ChartSystem`
  - `EconomySystem` (ledger, rent, wages, taxes, loans), `ContractSystem`
  - `PropertySystem`, `EmployeeSystem`, `CompanySystem`
- **Two detail levels**: the player and nearby/owned entities update per minute;
  the wider industry updates once per in-game day.
- **Seeded RNG**: a seeded random generator in state, so saves and tests are reproducible.
- **Money**: stored as integer cents to avoid floating-point drift.

## Content is data

Genres, subgenres, gear, loops, buildings, furniture, NPC name pools, platform
names and payout rates live in typed data files under `src/content/`. Balancing
means editing data, not code. Parody brand names live in one file.

## Saves

- Versioned save format with migration functions (`v1 → v2 → ...`) so updates
  don't break old saves.
- A single save per playthrough, autosaved each in-game day and on quit (no manual slots).
- Export/import as a `.json` file (Settings), via the share sheet on phones. Needed on
  iPhone because Safari and the home-screen app keep separate storage.

## Phones and the installable web app

- **Rendering:** the Phaser canvas renders at the device's pixel density and is shown at
  CSS size (`src/game/createGame.ts`). Scenes zoom by a whole number of *device* pixels
  per world pixel, so pixel art stays crisp and even on 2× and 3× screens. The camera
  viewport starts below the HUD, which reports its size through `ViewBridge.hudInsets`.
- **Layout:** `src/ui/styles/mobile.css` holds the touch and compact rules. "Compact"
  means a short landscape screen (≤ 520 px tall, i.e. phones); everything respects the
  `--safe-*` insets (notch, home indicator). Phones in portrait get a rotate notice.
- **Touch:** tap-to-move uses grid A* pathfinding (`src/game/pathfinding.ts`, unit tested);
  tapping furniture walks over and opens its action menu. An optional joystick writes a
  direction to `ViewBridge.joystick`.
- **Offline:** `vite.config.ts` emits `sw.js` from `src/pwa/sw-template.js` with the build's
  file list. Pages are network-first, files cache-first, one cache per build.
  `public/manifest.webmanifest` and the icons in `public/icons/` (generated by
  `scripts/make-icons.mjs`) make it installable.

## The world (Milestone 2)

- The simulation owns *where* you are (`player.location.area`: an `AreaId` from `src/content/city.ts`);
  `CitySystem` moves you between areas and emits `areaChanged`.
- One Phaser scene, `WorldScene`, builds whichever area you're in from its layout in
  `src/game/areas/layouts.ts` (art, colliders, usable objects, spawn points, lighting) and restarts
  itself on `areaChanged`. Streets are 640×192 world px and the camera follows the player; rooms are 288×192.
- Street life (pedestrians, cars) is view-only and not simulated.
- Signs use a 3×5 pixel font (`src/game/art/pixelFont.ts`) so they stay crisp.
- New systems: `CitySystem`, `GearSystem`, `LoopSystem`, `SocialSystem` (InstaSnap + ViewTube).
  Social link clicks reach the store through `BeatHubSystem.externalVisits`.

## Proposed folder layout

```
src/
  sim/              # pure simulation, no Phaser imports
    core/           # clock, event bus, RNG, command dispatcher, state types
    systems/        # one file/folder per system
    models/         # data types: Beat, Artist, Contract, Company...
  content/          # data: genres, gear, loops, brands, city, balance constants
  game/             # Phaser: scenes, tilemaps, player controller, NPC sprites
  ui/               # overlay UI: HUD, phone apps, DAW, menus
  audio/            # sequencer playback, sample loading
  save/             # persistence + migrations
  app/              # wires sim + Phaser + UI together (Session, ViewBridge)
tests/              # Vitest, including long headless economy runs
docs/               # design + architecture + roadmap
```

## UI design system: "studio hardware"

The pixel city is the world; the interface is the gear on your desk. Tokens live
in `src/ui/styles/tokens.css`.

| Role | Token | Value |
|---|---|---|
| Panels (sampler plastic) | `--chassis` | `#c4c2b8` |
| Silkscreen print | `--ink` | `#23221f` |
| LCD glass | `--lcd` | `#1f1810` |
| LCD segments (amber) | `--lcd-on` | `#ffb347` |
| Rubber keys | `--key` | `#3d3f47` |
| Live / destructive only | `--record` | `#d8432b` |

- **Type:** Pixelify Sans (display, used sparingly), Doto (dot-matrix LCD
  readouts, with unlit "ghost" segments behind), Schibsted Grotesk (body).
- **Signature:** the HUD is a tape transport. Game speed is set with transport keys
  (pause, play, fast-forward), each with an LED, and time and money show on LCDs.
- Panels are chassis cards with screws and silkscreened labels; buttons are rubber keys.
- Reduced motion is respected; keyboard focus is always visible.

## Quality rules
- `src/sim` must never import from `src/game` or `src/ui` (enforced by lint).
- Every system gets unit tests; the economy gets a headless "simulate 2 years" test with
  sanity bounds (no runaway inflation, no NaN money).
- A debug panel (toggle with backtick) to add money, skip time and inspect state.
